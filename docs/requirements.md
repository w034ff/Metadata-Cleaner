# 要件定義書

アプリ名は「Metadata Cleaner」とする。

## 1. 目的

写真や PDF には、撮影した場所（GPS）、日時、カメラの機種、作成者の名前など、見た目には現れない情報（メタデータ）が入っている。これらをオンラインのサービスにアップロードせず、手元の PC だけで取り除けるデスクトップアプリを作る。画質や見た目は変えない。GitHub で公開し、誰でも利用・ビルドできる状態にする。

## 2. 用語

| 用語 | 意味 |
| --- | --- |
| メタデータ | ファイルの見た目（画素、ページの内容）とは別に入っている情報。EXIF、XMP、IPTC、コメント、PDF の文書情報など |
| 消す | メタデータを取り除いた新しいファイルを書き出すこと。元のファイルは変えない |
| 残す情報 | 見た目を保つために必要なため、消さずに残す情報（画像の向き、色のプロファイルなど）。§FR-03 |
| 一覧 | 消すファイルを集めた表。PDF Converter の「PDF → 画像」の表と同じ作り |

## 3. スコープ

### 3.1 対象

- 画像（JPEG / PNG / WebP）と PDF からのメタデータの除去
- 画素とページの内容を変えない除去（画像の再エンコードをしない）
- 見つかったメタデータの種類の表示
- 単体と、フォルダ単位の一括の除去
- Windows と Linux 向けのデスクトップアプリ（Tauri 2）
- 日本語と英語の UI
- GitHub Releases でのバイナリ配布

### 3.2 初回リリースの対象外（後の版で検討する）

初回リリースには含めない。完成後の版上げで、要件を追加して取り組む候補とする。

- HEIC / AVIF / TIFF / GIF / BMP などの画像、Office 文書（docx / xlsx / pptx）、動画、音声
- 消す種類を選ぶ機能（「位置情報だけ消す」など）
- PDF の注釈の作成者名、フォームの値、添付ファイル、JavaScript の除去
- パスワードや権限で保護（暗号化）された PDF、電子署名付きの PDF（初回リリースでは、扱えない旨のエラーを表示する）
- 元のファイルの上書き
- サブフォルダの再帰的な一括処理
- コード署名
- macOS、ARM64、モバイル
- CLI 版

### 3.3 対象外

- 自動アップデート（アプリが通信しないこと（NFR-01）と両立しないため）
- 画素やページの内容に現れている情報（写り込んだ景色や文字、透かし、PDF の本文）の除去
- ファイル名に含まれる情報の除去

## 4. 利用環境

| 項目 | 要件 |
| --- | --- |
| Windows | Windows 10 / 11（x64）。WebView2 ランタイムがない環境ではインストーラーが導入する |
| Linux | x64、WebKitGTK 4.1 が利用できるディストリビューション（Ubuntu 22.04 以降相当） |
| ネットワーク | 不要。アプリは一切通信しない |

## 5. 機能要件

優先度は Must（初回リリースに必須）/ Should（初回リリースに含めたい）で示す。

### FR-01 入力（Must）

- 消すファイルを一覧に集めてから処理する。単体の処理と一括の処理は、どちらもこの一覧で行う。画面は 1 つで、タブは持たない。
- 一覧には、ファイル選択ダイアログ（複数選択可）、フォルダ選択ダイアログ、ドラッグ&ドロップ（ファイルとフォルダ）でファイルを追加できる。一覧から個別に外す操作と、すべて外す操作がある。
- フォルダを追加したときは、その直下にある対応拡張子のファイルだけを追加し、サブフォルダは見ない。
- 追加しようとしたもののうち、対応しない形式のファイルとサブフォルダは追加せず、その件数を表示する。
- 対応する拡張子は `.jpg` `.jpeg` `.png` `.webp` `.pdf`。大文字小文字を区別しない。拡張子と中身の形式が食い違うファイルの扱いは詳細設計で定める。
- 拡張子が対応していても中身を読めない場合は、そのファイルをエラーとして扱う。
- 大きさが上限を超えるファイル、オブジェクト数などが上限を超える PDF はエラーとして扱う。上限値は詳細設計で定め、名前付き定数にする。

### FR-02 一覧の表示（Must）

- 一覧は表で表示し、サムネイルは持たない。各行に、ファイル名、形式、ファイルの大きさ、見つかったメタデータの種類、処理の結果を表示する。
- 「見つかったメタデータの種類」は、位置情報、日時、機器（カメラの機種・シリアル番号など）、作成者・著作権、ソフトウェア、コメント、埋め込みのサムネイル、その他、のように利用者に分かる言葉でまとめる。分類は詳細設計で定める。
- 位置情報を含むファイルは、表の中で目立つように示す。
- 見つからなかったファイルは「メタデータなし」と表示する。この場合も処理の対象にでき、書き出したファイルは FR-04 を満たす。

### FR-03 消す情報と残す情報（Must）

- 画像（JPEG / PNG / WebP）から次を消す: EXIF（位置情報、日時、機器、ソフトウェア、メーカーノート、埋め込みのサムネイルを含む）、XMP、IPTC と Photoshop の情報、コメント（JPEG の COM、PNG の `tEXt` `zTXt` `iTXt`）、PNG の `tIME`、そのほか見た目に関わらない付加情報。
- PDF から次を消す: 文書情報（タイトル、作成者、件名、キーワード、作成・更新日時、作成ソフト、PDF 作成ソフト）、文書とページと各オブジェクトの XMP、過去の版（追記保存で残った以前の内容）、PDF の中の JPEG 画像に入っている EXIF・XMP など（画素は変えない）。文書の識別子（`/ID`）の扱いは詳細設計で定める。
- 次は見た目を保つために残す: 画像の向き（EXIF Orientation）、色のプロファイル（ICC）、画素を正しく読むのに必要な情報（JPEG の Adobe APP14、PNG の `gAMA` `cHRM` `sRGB` `cICP` `tRNS` など）。残す項目の正確な一覧は詳細設計で定める。
- 残した情報にも個人を特定できる内容が含まれうる場合（ICC の説明文など）の扱いは詳細設計で定める。

### FR-04 書き出し（Must）

- 保存先のフォルダを選び、元のファイル名のまま書き出す。元のファイルは変えない。保存先に元のファイルと同じフォルダは選べない。
- 同名のファイルがすでにある場合は上書きせず、`name (1).jpg` のように番号を付けて保存する。
- 画像は再エンコードしない。JPEG の圧縮データ、PNG の `IDAT`、WebP の画像データは、元のファイルとバイト列が同じになる。
- 元のファイルの更新日時、属性、代替データストリーム（Windows の Zone.Identifier など）は書き出したファイルに写さない。
- 書き出したあと、そのファイルを読み直して、消すべき情報が残っていないことを確かめる。残っていた場合は書き出したファイルを消し、その行を失敗とする。

### FR-05 一括の処理（Must）

- 開始すると、一覧のファイルをすべて処理する。処理中は一覧と保存先を変えられない。
- 進捗（完了件数 / 全件数）を表示し、キャンセルできる。1 ファイルの失敗で全体を止めない。終了時に成功・失敗の件数と理由を表示する。これらは PDF Converter の一括変換と同じ振る舞いにする。
- キャンセルしたとき、書き込み途中の不完全なファイルを保存先のフォルダに残さない。

### FR-06 詳細の表示（Should）

- 一覧の行を選ぶと、そのファイルで見つかったメタデータの項目と値（例: 緯度・経度、撮影日時、カメラの機種、作成者名）を表示する。
- 値はアプリの外に送らず、保存もしない。

### FR-07 多言語対応（Must）

- UI を日本語と英語で表示できる。エラーメッセージも両言語で用意する。
- 初回起動時は OS の言語設定が日本語なら日本語、それ以外なら英語で表示する。アプリ内で切り替えられ、次回起動時も切り替えた言語を使う。

### FR-08 ライセンス表示（Must）

- 「このアプリについて」画面で、バージョン、本アプリの MIT ライセンス、同梱している第三者ライブラリのライセンス一覧を表示する。

### FR-09 エラー表示（Must）

- 次の場合に、原因が分かるメッセージを表示する: 非対応形式、読み込みの失敗（壊れたファイル）、暗号化された PDF、電子署名付きの PDF、大きさの上限超過、書き込みの失敗（権限不足、ディスク容量不足など）、書き出し後の確認の失敗（FR-04）。
- エラーでアプリを終了させず、別のファイルを選び直せる状態に戻る。

### FR-10 設定の保持（Should）

- 最後に使った保存先のフォルダと言語を、次回起動時に復元する。

## 6. 非機能要件

### NFR-01 セキュリティ・プライバシー

- アプリは外部と一切通信しない。テレメトリ、自動アップデート確認、外部リソースの読み込みを含めない。Content Security Policy で外部への接続を禁止する。
- Windows の WebView2 ランタイム自身が行う通信の扱いは、PDF Converter と同じにする（止められるものは止め、止められないものは README に明記する）。
- Tauri の capabilities は必要最小限にする。ファイルの読み書きは、ユーザーがダイアログまたはドラッグ&ドロップで選んだファイル・フォルダに限る。
- 読み込んだメタデータの値は、画面に表示するほかはログにも設定ファイルにも書かない。
- 入力のファイルは外から来た信頼できないものとして扱う。壊れたファイルや細工されたファイルで読み込みの処理が異常終了・停止しても、アプリは終了しない。そのファイルを読み込みの失敗（FR-09）として表示し、続けて別のファイルを扱える。一括の処理では、そのファイルを失敗として残りを続ける。

### NFR-02 性能

- 12 メガピクセル・数 MB の JPEG 1 枚の処理が、基準環境で 0.5 秒以内に終わる。100 ページの PDF の目安は詳細設計で定める（基準環境も詳細設計で定める）。
- 処理中も UI は操作可能で、キャンセル操作は 1 秒以内に受け付けられる。
- 大きなファイルでもメモリを使い切らない。

### NFR-03 除去の品質

- 書き出した画像を読み込んだ画素が、元の画像と一致する。圧縮データは FR-04 のとおりバイト列が同じ。向きと色のプロファイルが元と同じ。
- 書き出した PDF は、一般的な PDF ビューアー（ブラウザー内蔵のものを含む）で開け、各ページを描画した結果が元の PDF と一致する。一致の確かめ方は詳細設計で定める。
- 書き出したファイルに、FR-03 で消すとした情報が残っていない。確認には、本アプリとは別の実装の道具（exiftool など）も CI またはテストで使う。

### NFR-04 配布

- GitHub の公開リポジトリで MIT ライセンスとして公開する。
- GitHub Actions で Windows と Linux 向けにビルドし、GitHub Releases に添付する（Windows: MSI と NSIS、Linux: AppImage と .deb）。
- コード署名は行わない。README に Windows SmartScreen の警告が出ることを記載する。

### NFR-05 ライセンス管理

- 依存ライブラリのライセンスは、MIT のアプリにバイナリで同梱できるものに限る。GPL / AGPL のライブラリは使わない。
- 第三者ライセンス一覧はビルド時に自動生成し、手作業で管理しない。
- CI で依存ライブラリのライセンスを検査し、許可リスト外のライセンスが混入したらビルドを失敗させる。テストでだけ使う道具（exiftool など）はアプリに同梱しない。

### NFR-06 品質・保守

- Rust の処理とフロントエンドのロジックに自動テストを用意し、CI で Windows と Linux の両方で実行する。
- テスト用の画像と PDF（フィクスチャ）はリポジトリに含める。フィクスチャに実在の人や場所の情報を入れない（位置情報は架空の値にする）。
- 既知の脆弱性の検査と依存の更新の自動化は PDF Converter と同じ仕組みにする。

### NFR-07 使いやすさ・外観

- 主要な操作はキーボードだけでも行える。
- ライト / ダークの配色を持ち、OS の設定に従って切り替わる。
- ウィンドウの最小サイズを定め、それ以上のどのサイズでも操作部品が重ならない。
- 高解像度ディスプレイ（表示倍率 100%〜200%）で文字やアイコンがぼやけない。
- 画面の作りと部品は PDF Converter に揃える。
- README と画面の説明で、消せない情報（§3.3）があることを伝える。

## 7. 受け入れ基準

初回リリースは、次をすべて満たしたときに受け入れる。

1. FR-01〜FR-05、FR-07〜FR-09 の Must 要件について、詳細設計で定めるテストがすべて合格する。
2. 画像: EXIF（位置情報・埋め込みのサムネイル・メーカーノート付き）、XMP、IPTC、コメント、ICC、向き（1〜8）を持つ JPEG、テキストのチャンクと `eXIf` と `iCCP` を持つ PNG、EXIF と XMP と ICC を持つ WebP から消し、NFR-03 を満たす。向きと色のプロファイルが残る。
3. PDF: 文書情報と XMP を持つ PDF、追記保存で過去の版を持つ PDF、EXIF 付きの JPEG を含む PDF から消し、NFR-03 を満たす。
4. 次の異常系で FR-09 のとおりにエラーが表示され、アプリが操作可能なまま残る。
   - 中身が壊れた画像と PDF、拡張子と中身が食い違うファイル
   - 暗号化された PDF、電子署名付きの PDF
   - 上限を超えるファイル
   - 読み込みの処理が異常終了・時間切れになった場合（テスト用の仕組みで起こす）
   - 書き込み権限のない保存先のフォルダ
5. 出力名が重なるケース（既存のファイルとの重複、同じ処理の中での重複）が、番号付きの別名で保存される。
6. 一括の処理を途中でキャンセルしたとき、保存先のフォルダに不完全なファイルが残らない。
7. Windows と Linux の両方で、GitHub Actions がビルドしたインストーラーからインストールして起動し、上記 2〜6 を手動で確認できる。
8. アプリの実行中に外部への通信が発生しない（NFR-01 の例外を除く）。
9. CI のライセンス検査が通り、「このアプリについて」画面に第三者ライセンス一覧が表示される。

## 8. 事前検証（スパイク）で決めること

- PDF を読み書きする crate: lopdf などの純 Rust のものと、pdfium などのネイティブのものを、過去の版を残さない書き直し、壊れた PDF への強さ、配布のしやすさで比べて選ぶ
- メタデータを読む方法: 既存の crate（kamadak-exif など）を使うか、JPEG のセグメント・PNG のチャンク・WebP の RIFF チャンクを自前で読むか
- 読み込みの処理を別プロセスで動かす必要があるか（NFR-01 の「アプリ全体が終了しない」を満たす方法）
- 向きの情報だけを残した EXIF の作り方（JPEG と WebP）
- PDF の描画結果の一致を確かめる方法（テストでだけ描画エンジンを使うか）

## 9. 詳細設計で決めること

- 画面構成（一覧の表の列、詳細の表示、保存先の欄、下部バー）
- 消す情報と残す情報の正確な一覧、メタデータの種類の分類
- PDF の `/ID` の扱い、拡張子と中身が食い違うファイルの扱い
- 大きさの上限値、性能の基準環境
- 設定の保存場所と形式
- Tauri の capabilities とコマンドの一覧
- 使用ライブラリとバージョン
